19. [ ] **security-reviewer** | `src/feedback.rs:288` | authentication / token predictability
   The slate token is the first 64 bits of SHA-256 over non-secret inputs: the query, the wall-clock nanosecond timestamp, the member count, the first member identity, and a 0..3 retry nonce (slate_token, src/feedback.rs:288-305). There is no CSPRNG input. A local actor who knows the query and can narrow the mint time can brute-force the token and forge feedback events against a slate they did not see. In the frozen local-CLI baseline this grants nothing beyond what direct write access to the SQLite file already grants (any local process can modify the repo DB), so it is hardening, not an exploitable boundary - but the baseline's declared question 'nonce source?' is answered negatively. CWE-330/CWE-341.
   *Recommendation:* Mint the token from OS randomness - rand 0.8 is already a non-dev dependency (Cargo.toml:109, used in src/bm25.rs and src/cluster.rs), so rand::rngs::OsRng (16 hex chars from 8 random bytes, keeping the PK-collision retry loop) costs nothing and future-proofs the token if the MCP surface ever gains a non-local transport.
