1. [ ] **code-quality-reviewer** | `src/output.rs:914` | output-correctness
   Piped `wonk contracts --format json` emits all rows on ONE line joined by ' ; ', not newline-delimited JSON. Mechanism: piped stdout gets an auto-budget (src/cli.rs:528-529, Some(2000)), so every format_contract call goes through budgeted_write -> emit(); emit's single_line branch collapses the row's newline to ' ; ' (src/output.rs:917-921) and its file-grouping heuristic reads the leading 'file:' token, which for JSON rows is the constant '{"kind"' — so every row lands in the same 'file' group and accumulates on one line. True NDJSON is produced only in TTY mode (single_line off, no budget). This violates the TASK-083 acceptance criterion 'NDJSON output is consumable without post-processing' (specs/tasks.md TASK-083) and the declared assumption 'per-row streaming NDJSON' in the piped mode agents actually consume. Mitigating context: `wonk ask` shares the same shape and ask_integration.rs blesses the same ' ; ' split, so this is a codebase-wide convention clash with the task-level AC rather than a contracts-only bug.
   *Recommendation:* Keep per-row newline delimiting for structured formats even in single-line mode — e.g. bypass the ' ; ' collapse in emit() when self.format.is_structured(), or render NDJSON rows directly in dispatch_contracts. Since `ask` uses the same seam, land the fix at the shared output layer and add one integration assertion that stdout.lines() each parse as a standalone JSON object. If the ' ; ' convention is ruled authoritative for this codebase, instead amend the test comment and the declared assumption so the AC is not recorded as satisfied by evidence that contradicts it.
