## Major

1. [ ] **architecture-alignment-checker** | `src/embedding.rs:860` | interface-contract
   Provider-scoped loaders only raise VectorSpaceMismatch when their filtered result set is empty. If even one active-provider vector exists, they silently discard every stored vector from another provider/dimension and run a partial semantic search. This can occur when an incremental provider switch or daemon re-embed completes only some symbols. DR-032 and PRD-EMB-REQ-005 require a stored provider/dimension mismatch to fail fast with re-embed guidance, rather than serve a mixed-transition index.
   *Recommendation:* Before returning provider-filtered vectors, detect any fresh embeddings in the requested scope whose provider or dimension differs from the active provider and return VectorSpaceMismatch whenever one exists. Apply the same invariant to all, path-prefix, and file-scoped loaders; add a test with both compatible and incompatible rows.

2. [ ] **code-quality-reviewer** | `src/embedding.rs:860` | error-handling
   All three embedding loaders check for an incompatible provider/dimension only when the compatible result set is empty (the equivalent guards are at lines 936 and 1021). A partially migrated index therefore returns only the new-provider subset while silently dropping old-provider vectors, rather than failing fast with the required re-embed instruction. This can occur after an interrupted provider rebuild and affects cluster, impact, and hybrid-search callers that load directly.
   *Recommendation:* Check the scoped embedding set for incompatible fresh rows before returning compatible vectors, regardless of result count, and replace the partial-partition success test with coverage that asserts the actionable mismatch error.

3. [ ] **code-quality-reviewer** | `src/router.rs:593` | error-handling
   `wonk update --skip-embed` eagerly constructs the configured provider before branching on `skip_embed`. Because the declared default is the deferred/unavailable `bundled` provider, the documented structural-only command exits with `embedding provider unavailable` instead of updating the index; this is reproducible with the default configuration.
   *Recommendation:* Only resolve/create the provider inside the embedding branches (or bypass it when `args.skip_embed` is true), and add a dispatch-level regression test proving `update --skip-embed` succeeds with no available embedding provider.
